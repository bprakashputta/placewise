## 2026-10-22 (Block 1)
- **Unrealistic career jumps in generated facts.** A sample candidate went from "Engineer in Training" to "Project Manager" with about 2 years of experience. *Cause:* each stint got one title from the person's level at the end of the career, so a long current job carried a senior title back to its start date. *Fix:* split stints at career-level boundaries (`_split_promotions`), so titles progress within the same employer.
- **"Updated resume" duplicates had a job ending before it started.** Example: a current job starting 2026-07 was closed at 2026-02. *Cause:* `_add_new_job` picked the end date without checking the current job's start. *Fix:* the new job must start at least 3 months after the previous one began; candidates who are too new in their role are skipped for this variant. A consistency check (ordering, overlaps, end ≥ start) now reports 0 problems across 500 candidates.
- **Tricky-case distribution too thin for key cases.** Only 1 "pursuing PE" in 500, and a median of 12 years' experience (too senior for a recruiting database). *Fix:* mid-career engineers without a PE list PE progress 45% of the time, and the experience distribution was shifted (median now 9.5 years).

- **Claude Haiku 5.5 rejected `temperature`.** All 10 first writes failed with `400 invalid_request_error: temperature is deprecated for this model`, at $0 cost since nothing was generated. *Fix:* removed `temperature`; variety comes from persona/layout/length instructions. *Second bug found by the same failure:* the writer retried this permanent 4xx error 3 times. Now 4xx errors (except 429) stop immediately, and rate limits and 5xx errors are retried with backoff by the SDK.
- **Generated resumes wrote empty sections** ("Licenses & Certifications: None listed."), found while reading the first 10 outputs. *Fix:* prompt **v2** adds "omit empty sections". v1 is kept for history, and each output records `prompt_version`. Also fixed: civil engineers were getting "LEED AP ID+C" (an interiors specialty); the LEED specialty now matches the discipline.
- **Prompt YAML failed to parse.** A changelog line contained `: ` and YAML read it as a mapping. *Fix:* quote changelog entries.

- **Owner review: resumes looked poor** (free-text v3: projects as bare bullets, thin jobs, odd "Sectors" section, layouts broken by heading-guessing, "SIDEBAR" printed literally, scan PDF showing boxes for missing glyphs). *Fix:* structured output (`StructuredResume` via LangChain `with_structured_output`), prompt v4/v5 content rules, five professional templates, glyph substitution and wrapping for scans. Lesson: generate structure and render it; never parse layout back out of free text.
- **Over-strict or missing checks found during review.** Software wasn't checked at all, so it could have been invented: now any known A/E/C tool not in the facts is flagged. "Open to relocation: No" appeared for non-relocators: now relocation is mentioned only when true. Then two checks were *too* strict: "utility relocation" (normal civil work) tripped the relocation rule, and "Revit" was flagged when the facts listed "Revit MEP". Both narrowed.
- **14 of 484 writes rejected: nested list in `extra_sections.items`.** Haiku sometimes returned `[["a","b"]]` for "Selected Projects" in long resumes. *Fix:* a `field_validator` flattens one level instead of rejecting. Rewrote only the 16 rejects: 16/16 accepted (total 484/484, about $0.64).
- **Render crashed (`KeyError: 'resume'`)** on resumes still in the old format. *Fix:* render skips rows not in the current structured format and reports how many.
- **Nested `KeepTogether` pushed whole sections to page 2** (the "keep heading with first item" fix). *Fix:* splice the first item's contents instead of nesting.
- **Viewer showed "intentionally corrupt" for a normal TXT file.** *Cause:* the endpoint assumed a missing preview meant corruption, and the showcase was stale. *Fix:* the server checks the file (a DOCX must be a zip archive); the viewer shows readable messages instead of raw JSON.
- **A safety check blocked `rm -f "$S"/*`** (an unguarded variable in rm). *Fix:* use `"${S:?}"/*`.

- **Partial render wiped the file index.** `render --ids C0501` rewrote `files.jsonl` with 1 entry, so the Seed page would have lost 596 files. *Cause:* the index was written from just-rendered items instead of merged. *Fix:* merge into the existing index (atomic replace).
